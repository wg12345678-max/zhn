## 附：回归测试修复记录（2026-10-15 第二轮）

本轮针对用户反馈的两个运行报错进行修复，并重跑 10/10 全部通过。

### 修复 1：TypeError — RecognitionCondition 对象不可下标
- **报错**：`TypeError: 'RecognitionCondition' object is not subscriptable`
- **位置**：`main_app.py` 第 265 行
- **根因**：`RecognitionCondition` 是 `@dataclass`，属性应用 `.` 访问，代码中误用 `c['threshold']` 字典下标
- **修复**：改为 `c.threshold` 属性访问

### 修复 2：ImportError — 无法导入 inject_anomalies / DEFAULT_SOURCE_WEIGHTS
- **报错**：`ImportError: cannot import name 'inject_anomalies'`
- **位置**：`main_app.py` 第 18 行
- **根因**：`deyang_generator.py` 重写时遗漏了这两个向后兼容接口
- **修复**：补齐 `inject_anomalies()` 与 `DEFAULT_SOURCE_WEIGHTS`，并让 `inject_anomalies` 返回 `(df, orders)` 元组以兼容新旧两种调用方式

### 修复 3：NumPy int32 溢出（银行卡号/PII 生成）
- **报错**：`ValueError: high is out of bounds for int32`
- **位置**：`_gen_pii()` 中 `np.random.randint(100000000000000000, 699999999999999999)`
- **根因**：数值超出 int32 上限
- **修复**：所有 PII/银行卡号改为纯字符串拼接生成，彻底规避溢出

### 修复 4：database.py 在特殊挂载文件系统下 disk I/O error
- **报错**：`sqlite3.OperationalError: disk I/O error`
- **位置**：`database.py` 的 `get_connection()` / `init_db()`
- **根因**：部分虚拟挂载文件系统不支持 SQLite 的 WAL/文件锁
- **修复**：启用 WAL + 30 秒超时 + 重试；并在默认路径不可写时自动回退到系统临时目录（`tempfile.gettempdir()`）
